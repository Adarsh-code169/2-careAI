# Deployment Guide

This project has two deployable parts:

| Part | Tech | Host | Why |
|------|------|------|-----|
| `backend/` | Node.js WebSocket server | **Render** | Needs a long-lived process for persistent WebSocket + STT/TTS streams. Vercel's serverless functions can't hold WebSockets open. |
| `voice-ui/` | Next.js (React) | **Vercel** | First-class Next.js hosting, global CDN, zero-config. |

The frontend talks to the backend over a single secure WebSocket (`wss://`). Get the backend live first, then point the frontend at it.

---

## Prerequisites

1. A **GitHub repo** containing this project (push it if you haven't).
2. API keys for the three providers:
   - **Deepgram** — https://console.deepgram.com (used for both STT and TTS)
   - **Groq** — https://console.groq.com (LLM)
   - **Tavily** — https://app.tavily.com (web search)
3. Free accounts on **Render** (https://render.com) and **Vercel** (https://vercel.com).

---

## Step 1 — Deploy the backend to Render

There is a `render.yaml` Blueprint at the repo root, so this is mostly automatic.

1. In Render, click **New + → Blueprint** and connect your GitHub repo.
2. Render reads `render.yaml` and proposes a web service named `voice-agent-backend`
   (root directory `backend`, build `npm install`, start `npm start`, health check `/health`).
3. Before the first deploy, fill in the environment variables it asks for:

   | Variable | Value |
   |----------|-------|
   | `DEEPGRAM_API_KEY` | your Deepgram key |
   | `GROQ_API_KEY` | your Groq key |
   | `TAVILY_API_KEY` | your Tavily key |
   | `ALLOWED_ORIGINS` | leave blank for now; you'll set it after the frontend is live |
   | `ADMIN_TOKEN` | auto-generated by Render (keep it secret) |
   | `SELF_PING_URL` | leave blank for now |

   > Do **not** set `PORT` — Render injects it and the server reads `process.env.PORT`.

4. Deploy. When it's live, note the URL, e.g. `https://voice-agent-backend.onrender.com`.
5. Verify the health check:
   ```bash
   curl https://voice-agent-backend.onrender.com/health
   # {"status":"ok","uptimeSec":12,"sessions":0}
   ```

### Prefer manual setup over the Blueprint?

New + → **Web Service** → connect repo, then set:
- **Root Directory:** `backend`
- **Build Command:** `npm install`
- **Start Command:** `npm start`
- **Health Check Path:** `/health`
- Add the same environment variables as above.

---

## Step 2 — Deploy the frontend to Vercel

1. In Vercel, **Add New → Project** and import the same GitHub repo.
2. Set the **Root Directory** to `voice-ui` (Vercel auto-detects Next.js from there).
3. Add an environment variable:

   | Variable | Value |
   |----------|-------|
   | `NEXT_PUBLIC_WS_URL` | `wss://voice-agent-backend.onrender.com` (your Render URL, **wss://**, no path) |

   > It must be `wss://` (secure). A browser served over HTTPS will refuse a plain `ws://` connection (mixed content).

4. Deploy. Note the frontend URL, e.g. `https://your-app.vercel.app`.

---

## Step 3 — Wire CORS + origin allowlist (close the loop)

Now that you know the Vercel URL, lock the backend down to it:

1. In Render → your service → **Environment**, set:
   ```
   ALLOWED_ORIGINS=https://your-app.vercel.app
   ```
   (Add more comma-separated, e.g. `https://your-app.vercel.app,http://localhost:3000` to keep local dev working.)
2. *(Optional, free tier)* To stop Render spinning the instance down after ~15 min idle, set:
   ```
   SELF_PING_URL=https://voice-agent-backend.onrender.com/health
   ```
3. Save — Render redeploys automatically.

---

## Step 4 — Verify end to end

1. Open the Vercel URL in Chrome.
2. Click anywhere to grant microphone permission and start a session.
3. Speak — you should see live transcripts, hear a spoken reply, and watch per-turn metrics in the sidebar.
4. Test **barge-in**: interrupt the assistant mid-sentence; its speech should cut off immediately.
5. *(Optional)* Test the admin context API with your `ADMIN_TOKEN` and a live `sessionId`
   (printed in the browser console as `[SESSION] Started: <id>`):
   ```bash
   curl -X POST https://voice-agent-backend.onrender.com/admin/context \
     -H "Content-Type: application/json" \
     -H "X-Admin-Token: YOUR_ADMIN_TOKEN" \
     -d '{"sessionId":"<id>","content":"You are a pirate. Answer in pirate speak."}'
   ```

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Avatar stays "idle", console shows WS errors | Frontend can't reach backend | Check `NEXT_PUBLIC_WS_URL` is the `wss://` Render URL with no trailing path |
| WS connects then immediately closes (403) | Origin blocked | Add the exact Vercel origin to `ALLOWED_ORIGINS` on Render |
| Mixed-content error in console | Used `ws://` from an HTTPS page | Use `wss://` |
| First request after idle is very slow | Render free tier cold start | Set `SELF_PING_URL`, or upgrade the plan |
| Backend won't boot, logs say "Missing required environment variables" | A provider key isn't set | Add the missing key in Render → Environment |
| `403 Admin API disabled` | `ADMIN_TOKEN` not set | Set `ADMIN_TOKEN` on the backend |

---

## Cost notes

- **Render free tier**: spins down on idle (cold starts of ~30–60s). Fine for demos; upgrade to a paid instance for always-on.
- **Vercel hobby tier**: free for personal projects.
- **Deepgram / Groq / Tavily**: usage-based; all offer free credits. Watch usage if the app is public.
